# Jana Address

Сервис разбирает адрес доставки, записанный одной строкой, на поля: область, город, район, жилой массив, улица, дом, квартира, подъезд, этаж, ориентир. Решение кейса хакатона Jana Post (Challenge 01).

Пример: `Туран 55/6 магазин береке 4подьезд 9этаж` даёт `street_name = "Туран"`, `house = "55/6"`, `entrance = "4"`, `floor = "9"`, `landmark = "магазин береке"`.

Разбор работает полностью локально и не обращается к внешним сервисам. Справочники лежат в репозитории и копируются в образ.

## Запуск

Нужен Docker с Docker Compose.

```bash
git clone https://github.com/keoj1t/post.git
cd post
docker compose up
```

Сборка образа требует интернета один раз (устанавливаются Python-зависимости из `requirements.txt`). После сборки сервис работает без сети.

Интерфейс: http://127.0.0.1:8080 (порт меняется переменной `JANA_PORT`). Документация API: http://127.0.0.1:8080/docs. Остановка: `Ctrl+C`.

Windows: можно запустить `START.bat` (Docker) или `START.bat --local` (локальный Python, виртуальное окружение `.venv` создаётся автоматически).

Локально без Docker на Linux или Mac:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python build_frontend.py
uvicorn app.main:app --host 127.0.0.1 --port 8080
```

## Интерфейс

1. Вставьте адреса в поле ввода или загрузите файл (JSON-массив записей или обычный список строк).
2. Нажмите кнопку разбора и дождитесь результата: сверху показывается число записей, время и сколько записей требуют проверки.
3. Записи с уверенностью ниже порога помечены. Для каждой показаны замечания (например, «не найден номер дома», «указано несколько разных номеров квартиры») с вариантами значений.
4. Поля можно поправить вручную и отметить запись как проверенную.
5. Результат скачивается в JSON или CSV либо копируется в буфер обмена.

Интерфейс двуязычный (русский и казахский).

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка состояния, ответ `{"status": "ok"}` |
| POST | `/parse` | Разбор одной записи |
| POST | `/parse/batch` | Пакетный разбор. Число и порядок записей в ответе совпадают со входом |

Вход принимается как массив записей, как объект с ключом `records`, `data`, `items` или `addresses` либо как одна запись. Строка вместо объекта тоже принимается и считается значением `raw_address`. Любая запись, которую не удалось разобрать, возвращается с `null` в полях и `confidence` 0.

Пример:

```bash
curl -X POST http://127.0.0.1:8080/parse/batch \
  -H "Content-Type: application/json" \
  -d '[{"id": "rec_00417", "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70"}]'
```

Ответ на каждую запись:

```json
{
  "id": "rec_00417",
  "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70",
  "province": "Алматы",
  "city": "Алматы",
  "district": null,
  "living_area": null,
  "street_type": "микрорайон",
  "street_name": "Аксай 3а",
  "house": "59",
  "apartment": "70",
  "entrance": null,
  "floor": null,
  "landmark": null,
  "postal_code": null,
  "building": null,
  "structure": null,
  "confidence": 0.95,
  "review": {"needs_review": false, "issues": []}
}
```

(Значения `district` и `confidence` в примере зависят от справочника OSM.)

### Поля

| Поле | Описание |
| --- | --- |
| `id`, `raw_address` | Возвращаются без изменений |
| `province` | Область («Актюбинская область») или город республиканского значения («Алматы») |
| `city` | Название населённого пункта без слов «город», «пос.» и без казахской половины |
| `district` | Район без слова «район»; если в строке нет, берётся из справочника |
| `living_area` | Микрорайон или ЖК, если улица указана отдельно |
| `street_type` | Тип улицы отдельным словом; если не указан в строке, определяется по справочнику, иначе `null` |
| `street_name` | Название без типа в том виде, как в строке (падеж и опечатки не меняются) |
| `house` | Номер дома с дробью и литерой: `1/2`, `12а` |
| `apartment`, `entrance`, `floor` | Только номер |
| `landmark` | Ориентир, например «магазин береке» |
| `postal_code`, `building`, `structure` | Индекс, корпус, строение (дополнительные поля) |
| `confidence` | Эвристическая уверенность от 0 до 1 |
| `review` | Замечания для оператора: `needs_review` и список `issues` с кодом, сообщением на русском и казахском, подсказкой и вариантами значения |

Поле, которое определить не удалось, равно `null`.

## Как устроен разбор

Код находится в `app/`. Основной конвейер `parse_address` в `app/parser.py` выполняет такие шаги:

1. **Очистка** (`clean`): нормализация Unicode, удаление невидимых символов (zero-width, мягкий перенос, BOM), лишних пробелов, исправление пробелов вокруг точек («Ул .Курильская»), замена «№» и дефисов у маркеров.
2. **Слитные строки** (`app/glued.py`, `split_glued`, `join_digit_runs`): «66квартал», «11дом», «4подьезд», «Назарбаева8», строки без пробелов вида «гУральскпрТулбаева12кв44».
3. **Нормализация** (`app/normalization.py`): словари маркеров полей, типов улиц, исправление опечаток («подьезд»), индекс, служебные пометки.
4. **Ключевые поля** (`extract_keyword_fields`): квартира, подъезд, этаж, дом, корпус по маркерам на русском, казахском и латинице (`кв`, `kv`, `flat`, `подъезд`, `этаж`, `floor`). Для каждого маркера число берётся слева или справа в зависимости от стиля записи в строке.
5. **Ориентиры и перекрёстки** (`extract_landmark`, `extract_intersection`, `extract_highway_route`).
6. **География** (`app/geo.py`): область, город и район сопоставляются со справочником КАТО (`reference/kato_ru.csv`). Двуязычные склейки через слэш сводятся к русской половине, дубли города убираются, район на месте города распознаётся.
7. **Улица и дом** (`parse_street`): тип улицы, название, номер дома. Номер микрорайона и квартала не принимается за номер дома.
8. **Справочник OSM** (`app/osm.py`): если район или тип улицы не указаны, они берутся из `reference/osm_streets.sqlite` по связке «город + название улицы». Значение подставляется, только если у большинства совпадений (не менее 50–60 %) оно одинаковое. Название улицы из справочника в ответ не подставляется: оно остаётся как в строке.
9. **Замечания и уверенность** (`app/review.py`, конец `parse_address`): формируется список замечаний и оценка `confidence` (например, 0.35 если дом не найден, 0.55 если остались нераспределённые числа, 0.95 если улица подтверждена справочником).

### Несколько номеров квартиры

Маркеры `кв`, `квартира`, `kv`, `flat`, `апт` означают квартиру. Если в строке квартира указана дважды с разными номерами («flat 191 kv 12»), берётся первое значение, а в `review` добавляется замечание `conflicting_apartment` с обоими вариантами, чтобы оператор выбрал нужный в интерфейсе.

## Справочные данные

| Файл | Источник | Содержимое |
| --- | --- | --- |
| `reference/kato_ru.csv` | Справочник КАТО | Иерархия областей, районов, городов и населённых пунктов |
| `reference/osm_streets.sqlite` | OpenStreetMap, дамп по Казахстану | Улицы, их типы и районы, места (микрорайоны, жилые массивы) |

Скрипт `scripts/build_osm.py` собирает SQLite из дампа `kazakhstan-latest.osm.pbf`. Дамп весит около 220 МБ, в репозиторий и в образ не входит (`.gitignore`, `.dockerignore`). Чтобы пересобрать справочник, положите дамп в `reference/` и запустите скрипт.

Справочник улиц и районов построен для около 190 городов и посёлков (все областные центры, города республиканского и областного значения и районные центры из OSM, у которых есть улицы с названиями), районы города есть у Астаны, Алматы, Шымкента и Тараза. Для остальных населённых пунктов остаются только улицы и типы.

Данные OpenStreetMap © участники OpenStreetMap, лицензия [ODbL](https://www.openstreetmap.org/copyright).

Запрещённые приёмы не используются: нет сопоставления по `id` записи и нет возврата готового ответа по точному совпадению входной строки.

## Тесты

Регрессионные тесты лежат в `tests/test_regressions.py`:

```bash
pip install pytest
pytest tests
```

## Необязательные функции


**Аккаунты.** Маршруты `/auth/*` (регистрация и вход, локальная база `data/accounts.sqlite3` в томе `accounts`) не нужны для разбора: `/parse` и `/parse/batch` работают без авторизации.

## Структура репозитория

```
app/
  main.py            FastAPI: /parse, /parse/batch, /health, карта
  parser.py          основной конвейер разбора
  glued.py           слитные строки
  normalization.py   словари маркеров, типов улиц, опечаток
  geo.py             КАТО: область, город, район
  osm.py             справочник OSM: район и тип улицы
  review.py          замечания для оператора
  auth.py            локальные аккаунты (необязательно)
  static/            интерфейс (собирается в index.html через build_frontend.py)
reference/           kato_ru.csv, osm_streets.sqlite
scripts/build_osm.py сборка справочника улиц из дампа OSM
tests/               регрессионные тесты
build_frontend.py    сборка интерфейса
docker-compose.yml, dockerfile, START.bat
```
